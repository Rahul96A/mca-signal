**Live deployment:** https://mca-signal.mangoground-b0b92773.centralindia.azurecontainerapps.io
— runs in live mode against the official data.gov.in company register (Azure Container Apps, Central India).
It scales to zero when idle, so the first request after a quiet period takes a few seconds, and lookups can be
temporarily unavailable when data.gov.in rate-limits the configured API key.

Research Indian private limited companies and LLPs by **company name, CIN, LLPIN, DIN or director name** and get a
provenance-tracked intelligence report: profile, filings timeline, financial analysis, charges, director network,
due-diligence signals and a cited AI report, exportable to PDF/CSV and shareable by link.

Every value in the UI and API carries its **source, category and freshness**, and the three kinds of information are
always distinguished:

| Badge | Meaning |
|---|---|
| **Official Government Data** | Ministry of Corporate Affairs master data via data.gov.in (GODL licence) |
| **Third-Party Aggregated Data** | A licensed MCA data API you configure |
| **AI-Derived Analysis** | Calculations, signals and narrative generated by this app from cited records |
| **Demo Data** | The bundled fictional dataset (used automatically when no provider is configured) |

> Financial values are labelled **Reported** (as provided), **Calculated** (same-year arithmetic on reported values,
> formula shown) or **Derived** (ratios/growth/CAGR). Missing values are shown as “—” and are never estimated.

## Quick start (no API keys, no services)

Requirements: Node.js 20+ (22 recommended).

```bash
npm install
npm run dev
```

Open http://localhost:3000. With no provider keys the app runs in **demo mode**: an embedded Postgres (PGlite, stored
in `.data/pglite`) is created, migrated and seeded automatically with 8 fictional companies, 2 LLPs, 18 directors,
170 filings, up to 5 years of financials and 16 charges. A demo login is created: **demo@mcasignal.local / demo12345**.

Try: `Brightwave` (typos work: `brihgtwave`), `U45200DL2009PTC999105`, `ZZA-0001`, DIN `99900104`, or press **Ctrl K**.

## Full stack with Docker (Postgres + Redis + worker)

```bash
cp .env.example .env        # optional — add keys for live data
docker compose up --build
```

Services: `app` (Next.js on :3000, runs migrations on start), `postgres` (16, with `pg_trgm`), `redis` (cache),
`worker` (background data sync).

## Using real data

| Variable | Purpose |
|---|---|
| `DATA_GOV_API_KEY` | Free key from data.gov.in. Enables official company/LLP master data. |
| `DATA_GOV_SYNC_STATES` | e.g. `karnataka,maharashtra` — states the worker bulk-imports for local fuzzy search |
| `MCA_PROVIDER`, `MCA_PROVIDER_API_KEY` (+ `MCA_PROVIDER_BASE_URL`, `MCA_PROVIDER_API_SECRET`, `PROBE42_ENV`) | Licensed third-party provider: `probe42` (financial statements, directors, charges), `attestr` (directors, charges, e-filings, fuzzy name search), `sandbox` (master data) or `generic` (your own adapter) |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | Optional LLM narrative for the report (rule-based narrative otherwise) |
| `DATABASE_URL` | PostgreSQL connection string (PGlite used when empty) |
| `REDIS_URL` | Redis cache (in-process LRU when empty) |
| `AUTH_SECRET` | ≥32 chars; **required in production** |
| `ADMIN_TOKEN` | Enables `POST /api/admin/sync` |
| `DATA_MODE` | `auto` (default), `demo`, or `live` |

When a live provider is configured (`DATA_MODE=auto` → live): an unknown CIN/LLPIN is fetched from providers in
priority order (official → third-party), normalised, stored with provenance, cached, and re-fetched after
`ENTITY_STALE_HOURS`. Demo data is not seeded in live mode.

**What is actually available** (verified 2026-09-23 — details in [docs/PROVIDERS.md](docs/PROVIDERS.md)):

* data.gov.in exposes live MCA **master data only** (3.67M companies + LLPs, updated 2026-07-22) with **exact-match**
  filters. Directors, filings, financials and charges are **not** in it.
* The MCA portal has **no public API**; its pages are CAPTCHA/login protected. This app does not scrape it or bypass
  any access control. Filing rows link to MCA *View Public Documents* for users to obtain documents themselves.
* Directors/filings/financials/charges therefore require a licensed third-party API. Without one those sections show
  “not available from configured sources”, and dependent checks are skipped rather than guessed.

### Background sync

```bash
npm run worker        # loop (WORKER_INTERVAL_MINUTES, default 360)
npm run sync:ogd      # one pass and exit
```

Imports data.gov.in master data page by page (resumable offset stored in `data_sync_logs`) and refreshes stale
entities. With PGlite only one process can open the database — stop `npm run dev` first, or use Postgres, or call:

```bash
curl -X POST localhost:3000/api/admin/sync -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" -d '{"job":"ogd_bulk","state":"karnataka","maxPages":5}'
```

## Architecture

```
Browser (Next.js pages, React Query)
   │  only calls /api/* — never provider APIs; no secrets in the browser
   ▼
API routes (src/app/api)  ── rate limiting, error envelope, logging (src/lib/api.ts)
   ▼
Services (src/lib/services) ── entity resolution, search, network, report, export, sync
   │            │
   │            └─ Analysis (src/lib/analysis): financials · risk signals · data quality · fuzzy match
   ▼
Provider registry (src/lib/providers) ── DataGov · Probe42 · Attestr · Generic/Sandbox · Demo
   ▼                                        (same contract; swap without touching the frontend)
Normalised DB (src/lib/db) ── PostgreSQL / PGlite, provenance on every row  +  cache (Redis / LRU)
```

**Search → identification → retrieval → normalisation → database → analysis → report → export** is one path:
`resolveEntity()` looks up the DB, calls providers when missing/stale, `persistBundle()` normalises and upserts with
provenance, `getDossier()` runs financial analysis, signals and data-quality scoring (cached), and the report/export
services render from the same dossier.

### Database

Tables: `companies, llps, directors, company_directors, filings, financials, charges, company_name_history, addresses,
data_sources, data_sync_logs, reports, users, watchlists` (+ `schema_migrations`). Every data table stores
`source_id, source_record_id, fetched_at, published_at, last_updated_at, raw_response_hash`. Child tables belong to
exactly one company or LLP (`check (num_nonnulls(company_id, llp_id) = 1)`). Trigram GIN indexes power fuzzy search.
Schema: [src/lib/db/migrations.ts](src/lib/db/migrations.ts).

```bash
npm run db:migrate            # apply migrations (add -- --reset to drop & recreate)
npm run db:seed               # load demo data + demo user (-- --force to reload)
```

### AI report

Built from a **fact base** in which every fact has a record reference (`filing:<id>`, `fin:<id>`, `charge:<id>`,
`role:<id>`, `profile:<field>` …). The narrative (sections 1–9) is written by OpenAI when `OPENAI_API_KEY` is set,
otherwise by a deterministic rule-based writer. LLM output is **validated**: paragraphs whose citations don't resolve
to a real record are dropped, and if too little survives the rule-based version is used. Sections 10–12 (sources,
freshness, limitations) are always deterministic. Reports are stored per data snapshot with an unguessable share token
(`/company/<id>/report?share=<token>`).

### Due-diligence signals

Status not active · recent / frequent director changes · open charges (vs net worth) · large recent charges ·
filings delayed vs provided or statutory-estimate due dates · expected annual filings not found · capital changes ·
registered-office changes · no revenue / repeated losses / negative net worth · no recent filings · directors linked to
inactive entities · sections unavailable. Wording is neutral (“Potential review item”, “Data point requiring further
verification”, “Filing appears delayed based on available dates”) and each signal lists its evidence records.

## API

All responses: `{ data, meta: { dataMode, sources?, page?, pageSize?, total?, generatedAt } }` or
`{ error: { code, message } }`.

| Method & path | Description |
|---|---|
| `GET /api/search?q=&type=all\|company\|llp\|director&page=&pageSize=` | Fuzzy name / CIN / LLPIN / DIN search |
| `GET /api/companies/:cin` | Profile, signals, data quality, summary (accepts LLPINs) |
| `GET /api/llps/:llpin` | Same for LLPs |
| `GET /api/companies/:id/directors` | Current & former directors / partners |
| `GET /api/companies/:id/filings?page=&pageSize=&formType=&year=&delayedOnly=1` | Paginated filing timeline |
| `GET /api/companies/:id/financials` | Per-year metrics with basis, YoY, ratios, CAGR |
| `GET /api/companies/:id/charges` | Charges + open/satisfied summary |
| `GET /api/companies/:id/network?depth=1..3` | Relationship graph + common directors |
| `GET/POST /api/companies/:id/report` | Cited report (POST regenerates) |
| `GET /api/companies/:id/export?format=pdf` / `?format=csv&section=…` | Exports |
| `GET /api/directors/:din` | Director with current/previous companies, co-directors |
| `GET /api/reports/:shareToken` | Shared report snapshot |
| `GET /api/meta/sources` | Providers, capabilities, sources, sync logs |
| `POST /api/auth/register \| login \| logout`, `GET /api/auth/me` | Basic auth (bcrypt + httpOnly JWT cookie) |
| `GET/POST /api/watchlist`, `DELETE /api/watchlist/:identifier` | Watchlist (signed-in) |
| `POST /api/admin/sync` | Trigger sync jobs (Bearer `ADMIN_TOKEN`) |
| `GET /api/health` | Health check |

## Tests

```bash
npm test          # vitest: unit + API tests (in-memory PGlite, no network)
npm run typecheck
```

* Unit: identifier parsing, fuzzy matching, financial calculations (never fabricates), CAGR rules, risk signals
  (incl. banned-accusation wording check), due-date estimates, data.gov.in mapping (real recorded responses),
  third-party schema validation, HTTP retry/backoff & secret redaction, CSV injection escaping, AI citation
  validation, rate limiting.
* API: every endpoint end-to-end over the real stack, auth + watchlist flow, and a live-mode pipeline test with a
  stubbed provider (fetch → normalise → store with provenance → serve; failure → 502 + sync log).

## Limitations

* Demo entities are fictional; identifiers use unallotted ranges (CIN reg. no. `999xxx`, DIN `9990xxxx`, LLPIN `ZZA-`).
* Filing delays use provided due dates or statutory estimates; AGM extensions and MCA relaxation circulars are not
  modelled. Charge amounts are secured amounts, not outstanding balances.
* The API rate limiter is per process; use a gateway or Redis-backed limiter for multi-instance deployments.
* Not legal, financial or credit advice.
